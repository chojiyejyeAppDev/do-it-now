## 1. 분류별 합계가 마지막 항목을 빠뜨린다 (주 실습)

`src/stats.js`의 `totalByCategory()`:

```js
for (var i = 0; i < items.length - 1; i++) {   // ← 여기
```

`- 1` 때문에 마지막 항목이 합계에서 빠진다. 지워서 `i < items.length` 로 고친다.

- 실패하던 테스트: **"분류별 합계가 모든 항목을 포함한다"**
- 고치면 통계 화면 합계가 `3,284,933원` → `3,290,333원`이 된다.
  (아직 `3,290,334원`이 아닌 이유는 2번 결함이 남아 있기 때문이다 — 1원 차이.)

## 2. 금액 반올림이 잘림으로 되어 있다 (보조)

`src/money.js`의 `roundWon()`:

```js
return parseInt(n, 10);   // ← 소수점을 버린다. 음수에서는 방향까지 달라진다.
```

`Math.round(n)` 으로 바꾼다. `parseInt(-4166.6)`은 `-4166`이지만 `Math.round(-4166.6)`은 `-4167`이다.

- 실패하던 테스트: **"음수 금액도 올바르게 반올림한다"**

## 3. 한 자리 달을 못 찾는다 (선택·심화)

`src/stats.js`의 `filterByMonth()`:

```js
var key = year + '-' + month;   // 2025 + '-' + 9  →  "2025-9"
```

날짜는 `"2025-09-02"` 형식이라 앞 7자는 `"2025-09"`다. `"2025-9"` 와는 절대 같아지지 않는다.
9월만 0건이 나오고 10·11·12월은 정상인 이유가 이것이다.

```js
var key = year + '-' + String(month).padStart(2, '0');
```

- 실패하던 테스트: **"한 자리 달도 그 달의 항목을 찾아낸다"**

- **되돌리기**: `git checkout -- src/stats.js` 로 한 파일만 원래대로. 되돌리면 빨강이 다시 3개로 돌아온다.
- **diff를 보고 거부하기**: Claude Code가 제안한 수정이 결함과 무관한 부분까지 건드리면 거부한다.
  거부는 정상적인 사용법이다.
- **테스트가 판정한다**: "고쳐진 것 같다"와 "고쳐졌다"를 가르는 것은 화면의 초록·빨강이다.
