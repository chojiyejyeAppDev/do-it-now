# 저장소 상태 명세 (회사 운영용)

이 문서는 학습자용이 아니라 **회사가 저장소를 유지보수할 때 쓰는 계약서**다.
회차 원고의 성공 기준은 아래 숫자에 묶여 있다. 이 값이 바뀌면 발행된 원고가 전부 틀린다.

## 숫자 계약 (2026-08-23, 실행으로 확정)

| 이름 | 값 | 의미 |
|---|---|---|
| `T_all` | **3,290,334원** | 결함을 모두 고쳤을 때의 샘플 60건 전체 합계 |
| `T_bug` | **3,284,933원** | `main` 상태에서 통계 화면에 실제로 표시되는 합계 |
| `T_food` | **200,600원** | 전 기간 식비 합계 (결함 유무와 무관하게 같다) |
| `T_food_2025_12` | **47,900원** | 2025년 12월 식비 합계 — 9회 MCP 질문의 정답 숫자 |
| `N_total` | 브랜치마다 다름 | 아래 표 참조 |

샘플 데이터는 가상 인물 "김하늘"의 **2025-09 ~ 2025-12** 지출 60건이다.
달을 이 구간으로 잡은 이유는 **한 자리 달이 09 하나뿐**이어서 BUG-03의 증상이
"9월만 0건, 다른 달은 정상"으로 깨끗하게 관찰되기 때문이다. 달 구간을 바꾸면 BUG-03이 무너진다.

## 브랜치별 상태

| 브랜치 | 남아 있는 결함 | 테스트 | 특이사항 |
|---|---|---|---|
| `main` | BUG-01, BUG-02, BUG-03, BUG-04, BUG-05, GAP-01 | **17개 중 14개 통과 / 3개 실패** | 3회 시작점. 1회 재실습도 여기 |
| `start/ep05` | BUG-04, BUG-05, GAP-01 | **19개 중 18개 통과 / 1개 실패** | CLAUDE.md 없음(의도) |
| `start/ep07` | BUG-05, GAP-01 | **19개 중 19개 통과 / 0개 실패** | CLAUDE.md 있음, `.claude/` 비어 있음 |
| `start/ep09` | BUG-05, GAP-01 | **19개 중 19개 통과 / 0개 실패** | `mcp/` 추가, `.mcp.json` 없음 |
| `start/ep11` | BUG-05, GAP-01 | **22개 중 19개 통과 / 3개 실패** | CSV 테스트 3건 추가, `.claude/agents/` 비어 있음 |

**빨강 3개가 나오는 이유(main)**: 결함 하나에 실패 테스트 하나씩 대응한다.
BUG-01 → "분류별 합계가 모든 항목을 포함한다" / BUG-02 → "음수 금액도 올바르게 반올림한다" /
BUG-03 → "한 자리 달도 그 달의 항목을 찾아낸다". 하나를 고칠 때마다 빨강이 하나씩 줄어든다.

> ⚠️ **설계서와 달라진 점.** ED-06 설계서(§4 3회 행)는 `main`을 "1개 실패"로 적었으나,
> 같은 설계서 §5가 3회에 BUG-01(주)·BUG-02(보조)·BUG-03(선택)을 **모두** 배치했다.
> 결함 3건을 심고 실패를 1건만 보이게 하려면 두 결함을 테스트 밖에 둬야 하는데,
> 그러면 §5의 원칙 ①("모든 결함은 테스트로 잡힌다")이 깨진다. 원칙을 지키는 쪽을 택해
> **3개 실패**로 확정했다. 3회 원고의 성공 기준 문장은 아래로 교체해야 한다.
> - ① `tests.html`을 열면 `17개 중 14개 통과 / 3개 실패`가 보인다
> - ③ 주 결함을 고치면 `2개 실패`로 줄고, 셋을 다 고치면 `17개 전부 통과`가 된다
> - ④ 되돌리기 후 다시 열면 다시 `3개 실패`로 돌아온다

## 유지보수 규칙

1. **`main`의 결함 3건을 실수로 고치지 마라.** 개선 커밋을 넣기 전에 `node tests/run.js`를 돌려
   실패가 정확히 3개인지 확인한다.
2. 회차를 발행할 때 그 시점의 상태를 태그로 고정한다: `git tag v1-ep03 main`.
3. 샘플 데이터를 바꾸면 위 숫자 계약이 전부 바뀐다. 바꿔야 한다면 `node tests/run.js`로
   새 값을 뽑아 이 문서와 각 회차 원고를 **같은 숫자로** 갱신한다.
4. 코드는 `data/sample-expenses.js` **한 파일**을 브라우저와 Node가 공유한다.
   설계서는 `.json`을 적었으나, 브라우저에서 파일을 직접 열면(`file://`) JSON을 읽어 올 수 없어
   `.js`로 바꿨다. 두 벌 관리를 피하기 위해 `.json`은 두지 않는다.
